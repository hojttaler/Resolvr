# Resolvr

GraphQL-клиент для macOS: не теряет состояние, выглядит нативно и доступен агенту
через MCP.

Заменяет Apollo Explorer в двух вещах, которых там не хватало: вкладки и черновики
переживают перезапуск и краш, а Claude Code может сам собирать коллекции, гонять
запросы и smoke-тесты через тот же движок, что и приложение.

Инструкция для коллег — как установить DMG, пройти Gatekeeper, подключить общий
workspace и агента: [INSTALL.md](INSTALL.md). Английская версия — [../README.md](../README.md).

## Быстрый старт

```bash
pnpm install
pnpm --filter @resolvr/mock-server start   # тестовый GraphQL на :4000
pnpm dev                                     # приложение в dev-режиме
```

Релизная сборка: `pnpm --filter @resolvr/desktop build` → `.app` и `.dmg` в
`apps/desktop/src-tauri/target/release/bundle/`.

Установка или обновление в `/Applications` одной командой:

```bash
pnpm install:app
```

Скрипт закрывает запущенный экземпляр, копирует бандл через `ditto` и восстанавливает
ad-hoc-подпись — обычный `cp -R` ломает её, и приложение перестаёт проходить проверку
`codesign`.

DMG для раздачи (universal: Apple Silicon + Intel): `pnpm release` → `dist/`.
Сборки под Linux и Windows — в CI (`.github/workflows/build.yml`), с Mac они не
кросс-компилируются.

## Что внутри

| Пакет | Роль |
|---|---|
| `apps/desktop` | Приложение: Tauri v2 (Rust) + React 19 + CodeMirror 6 |
| `packages/core` | Ядро: модель, хранилище, движок запусков, флоу, схема |
| `packages/mcp-server` | MCP-сервер поверх того же ядра |
| `tools/mock-server` | Тестовый GraphQL с подпиской и логином |

Ядро не зависит ни от Tauri, ни от Node: сетевой транспорт, хранилище секретов и
файловая система спрятаны за интерфейсами (`packages/core/src/ports`). Приложение
подставляет Rust-реализации, MCP-сервер — реализации на Node. Поэтому операция,
сохранённая агентом, немедленно появляется в открытом приложении, а флоу ведёт себя
одинаково при ручном и автоматическом запуске.

## Хранилище

Всё лежит плоскими файлами в `~/Resolvr` — их можно читать, править руками и
версионировать в git:

```
~/Resolvr/
├─ settings.json
├─ workspaces/<workspace>/
│  ├─ workspace.json               эндпоинты, окружения, раскладка панелей
│  ├─ collections/<collection>/
│  │  ├─ collection.json
│  │  ├─ getUser.graphql           текст запроса
│  │  └─ getUser.meta.json         переменные, заголовки, описание
│  ├─ flows/<flow>.flow.json       цепочки и smoke-тесты
│  ├─ .cache/schema.<endpoint>.json    SDL + предыдущий снимок для diff
│  └─ .history/YYYY-MM-DD.jsonl    журнал запусков
└─ .state/
   ├─ session.json                 открытые вкладки
   └─ drafts/<tabId>.graphql       несохранённый текст каждой вкладки
```

Все записи атомарны (`tmp` → `rename`), история — append-only. Приложение переживает
`kill -9` без потери набранного текста и без порчи файлов.

**Секреты** в файлы workspace не попадают. В `workspace.json` хранится только ссылка
`keychain://<workspace>/<environment>/<key>`; значение живёт в `.secrets/` библиотеки
(доступ только владельцу) или в macOS Keychain — по выбору в настройках — и
маскируется везде, где ответ покидает процесс: в истории, в панели заголовков и в
ответах MCP.

## Настройки

Шестерёнка в правом верхнем углу, `⌘,` или палитра команд. Внутри: тема
(системная/светлая/тёмная), **прозрачность окна** и материал нативного размытия,
размер шрифта редактора, размер отступа, номера строк, перенос длинных строк,
глубина автозаполнения выборки, таймаут запроса, глубина раскрытия дерева ответа и
срок хранения истории.

Прозрачность устроена в два слоя: материал (`NSVisualEffectMaterial`) задаёт саму
плотность нативного размытия и переключается Rust-командой, а ползунок добавляет
поверх него фон нужной плотности — от чистого материала до полностью непрозрачного
окна. Всё применяется сразу и
сохраняется в `settings.json`; смена шрифта и темы не пересоздаёт редакторы, поэтому
история отмен и позиция курсора не теряются.

## Работа со схемой

Клик по полю в панели «Схема» вставляет готовую операцию: выборка раскрывается на три
уровня, обязательные аргументы превращаются в переменные, скелет значений
подставляется автоматически. Циклические связи (`User.friends: [User]`) обрываются, а
поля с обязательными аргументами не разворачиваются — угадать их значение нельзя, и
неполный запрос всё равно не выполнился бы.

`Инспектор → Сравнить со снимком` показывает, что изменилось в схеме с прошлой
интроспекции, отмечая ломающие правки (удалённое поле, изменившийся тип, новый
обязательный аргумент).

При наборе запроса вручную выбор поля из подсказки сразу даёт рабочий фрагмент:
обязательные аргументы подставляются как переменные (`products(input: $input)`),
переменные объявляются в заголовке операции, а панель переменных получает их скелет.
Переменная того же типа переиспользуется, при конфликте типов имя получает суффикс;
анонимная операция `{ … }` превращается в `query ( … ) { … }`, потому что объявить
переменные иначе нельзя. Поля объектного типа при этом раскрываются вложенной
выборкой (`fillLeafsOnComplete`).

Панель переменных тоже знает схему. В позиции имени предлагаются переменные операции
и поля input-типа, в позиции значения — варианты enum и `true`/`false` для булевых
полей. Что именно набирают, определяется по тексту слева от курсора: синтаксическое
дерево на недописанном JSON восстанавливается непредсказуемо, а двоеточие перед
курсором — надёжный признак. Кнопка «Заполнить из запроса» разом подставляет все
переменные операции со значениями по их типам, не затирая уже введённые.

## Заголовки

Общие заголовки задаются один раз в `⌘⇧,` (Файл → Настройки workspace) и
применяются ко всем запросам. Порядок наложения — от общего к частному:

```
эндпоинт → окружение → коллекция → операция → вкладка → auth-профиль
```

Во вкладке «Заголовки» унаследованные показаны отдельным блоком с указанием
источника: видно, откуда берётся `Authorization`, которого нет в самой вкладке.

## Проверка переменных

Перед отправкой переменные сверяются со схемой: незаполненные обязательные поля,
неверные типы, недопустимые значения enum и лишние ключи находятся локально. При
ошибке запрос не уходит — панель ответа показывает список замечаний с путём до
конкретного поля и кнопкой «Всё равно выполнить». Предупреждения (лишнее поле,
необъявленная переменная) выполнению не мешают.

## Цепочки, привязанные к запросам

Одну и ту же подготовку не нужно повторять руками:

- **Подготовка.** У сохранённой операции выбирается цепочка в шапке панели
  запроса («Перед: Авторизация»). Она выполняется до запроса, а извлечённые
  значения подставляются в переменные и заголовки как `{{token}}`.
- **Восстановление.** В настройках окружения выбирается цепочка, которая
  запускается при ошибке авторизации (по HTTP-статусу или тексту ошибки), после
  чего запрос повторяется автоматически. Это снимает цикл «получил 401 → сходил
  за токеном → подставил заголовок → повторил».

Шаги самих цепочек своих цепочек не запускают, а неудачное восстановление
прекращает повторы — иначе протухшая сессия давала бы бесконечный цикл.

## Авторизация

Токен, добытый цепочкой, сохраняется: значение уходит в Keychain, в переменные
окружения записывается ссылка на него, а срок жизни берётся из `exp`. Без этого
значение жило только внутри одного запроса — заголовок `Bearer {{accessToken}}`
снова оказывался нераскрытым, и логин повторялся перед каждым вызовом.

Из сохранённого срока следуют три вещи:

- **токен обновляется заранее** — за минуту до истечения цепочка восстановления
  запускается сама, без круга «запрос → отказ → логин → повтор»;
- **состояние видно в шапке** — «токен 12 мин», жёлтый на исходе, красный после
  истечения; клик запускает обновление вручную;
- **владелец известен** — `sub` из токена показывается в подсказке, видно, под кем
  уходят запросы.

У окружения есть профиль:

- `bearer` — токен берётся из переменной окружения (обычно ссылки на Keychain);
- `login` — приложение само выполняет операцию логина, достаёт токен по указанному
  пути (`data.login.accessToken`), кладёт его в Keychain и переиспользует, пока не
  истечёт TTL. Ручное копирование токена в заголовки не требуется.

## Цепочки запросов и smoke-тесты

Сайдбар → вкладка **Флоу** → «+ Создать цепочку». В редакторе шаг берёт либо
сохранённую операцию, либо свой запрос; поле «Извлечь» кладёт значение из ответа в
контекст (`data.login.accessToken` → `token`), а следующие шаги подставляют его в
переменные как `{{token}}`. «Проверки» — утверждения о результате шага. Кнопка
«Сохранить и запустить» показывает результат прямо у шагов; ▶ в списке запускает
цепочку без открытия редактора.

После запуска под каждым шагом раскрывается его полный ответ. Пути не нужно набирать
руками: кнопка **↧** у любого поля ответа добавляет его в «Извлечь», а ⌥-клик по ней —
в «Проверки». Поля путей дополнительно подсказывают пути из последнего ответа. Внизу
диалога — итог цепочки: все извлечённые значения с кнопкой копирования.

На диске это `flows/<name>.flow.json` — файл можно править руками и коммитить:

```json
{
    "id": "smoke",
    "name": "Логин и профиль",
    "steps": [
        {
            "id": "login",
            "name": "Логин",
            "operationRef": "auth/login",
            "extract": { "token": "data.login.accessToken" },
            "assert": [{ "path": "data.login.accessToken", "op": "exists" }]
        },
        {
            "id": "me",
            "name": "Профиль",
            "operationRef": "users/me",
            "assert": [{ "path": "data.me.id", "op": "eq", "value": "u1" }]
        }
    ]
}
```

Падение шага останавливает флоу, остальные помечаются пропущенными — если шаг явно не
помечен `continueOnFailure`.

## Доступ для агента (MCP)

```bash
pnpm --filter @resolvr/mcp build
claude mcp add resolvr --scope user -- node <путь>/packages/mcp-server/dist/index.js
```

**Работа со схемой экономна по контексту.** У реального гейтвея схема — около
мегабайта SDL (2 700 типов, 1 500 корневых операций), и отдавать её целиком значит
занять сотни тысяч токенов на один вызов. Поэтому `schema_get` без аргументов
возвращает оглавление (счётчики и образцы имён), `search` ищет поле или тип по
подстроке, `list` отдаёт раздел операций постранично, `typeName` печатает один тип
с ограничением по числу полей. Полный SDL доступен по явному `full: true`.

Любой ответ инструмента обрезается на 40 000 символах с подсказкой, как забрать
нужное точечно; `run` принимает `select` — путь к части ответа.

Инструменты: `plan`, `note`, `workspace_list`, `workspace_create`, `collection_list`,
`collection_create`, `operation_get`, `operation_save`, `operation_delete`, `run`,
`introspect`, `schema_get`, `schema_diff`, `flow_list`, `flow_run`, `env_list`,
`env_set`, `history_list`.

### Наблюдение за агентом

`⌘⇧A` (или значок списка в шапке) открывает журнал действий: слева хронология —
план, каждый вызов с намерением и результатом, заметки и ошибки; справа полные
аргументы и ответ выбранного шага. Фильтры показывают только ошибки или только
выводы агента, а панель обновляется по мере работы — за агентом можно следить в
реальном времени, а не разбирать итог постфактум.

Агент обязан объяснять свои действия: `intent` — обязательное поле каждого вызова,
`plan` объявляется первым вызовом, `note` фиксирует выводы. Вызов без намерения
отклоняется валидацией, поэтому журнал не может оказаться безымянным списком
дёрганий API. Неудачные вызовы записываются наравне с успешными — без них картина
работы выглядела бы искусственно гладкой.

Журнал лежит в `~/Resolvr/.activity/YYYY-MM-DD.jsonl`, сгруппирован по сессиям
MCP-сервера, секреты в нём замаскированы, а слишком длинные ответы усечены.

Сервер работает независимо от приложения и с той же библиотекой. Корень можно
переопределить переменной `RESOLVR_HOME` — так устроена сквозная проверка
`pnpm --filter @resolvr/mcp test:e2e`, которая не трогает рабочие данные.

## Витрина интерфейса

```bash
pnpm dev                                  # или pnpm --filter @resolvr/desktop vite
pnpm --filter @resolvr/desktop shots    # скриншоты всех экранов в /tmp/gqlai-shots
```

`showcase.html` рендерит настоящие компоненты с готовыми данными вне Tauri, а
`scripts/shots.mjs` снимает их через Playwright. Так оформление проверяется
скриншотами, а не перебором состояний в собранном приложении; заодно скрипт
сверяет контраст обеих тем и падает, если светлая снова окажется белым по белому.

## Детали реализации, которые стоит знать

**HTTP идёт через Rust.** Webview подчиняется CORS, а dev-эндпоинты его почти никогда
не настраивают. Заодно там же живут точные тайминги и приём самоподписанных
сертификатов (`acceptInvalidCerts` у эндпоинта). Подписки, наоборот, открываются
прямо из webview — на WebSocket CORS не распространяется.

**Прозрачный фон обязателен.** Под окном работает `NSVisualEffectView`
(`macOSPrivateApi: true`), поэтому ни `body`, ни панели не имеют непрозрачного фона —
только полупрозрачные слои поверх системного размытия.

**Скрытые каталоги в scope файлового плагина.** На unix Tauri по умолчанию не даёт
glob-шаблонам матчить пути, начинающиеся с точки, поэтому в `tauri.conf.json` задано
`plugins.fs.requireLiteralLeadingDot: false` — иначе `.state` и `.history` были бы
недоступны приложению.

**Ограничения текущей версии.** Свободное перетаскивание панелей (только три пресета),
импорт из Postman/Apollo, генерация кода и diff ответов между запусками не сделаны.
Сборка ad-hoc-подписанная, без нотаризации и автообновлений.
