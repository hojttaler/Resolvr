# Resolvr 0.2.0

The schema becomes a place you can read, not only autocomplete against — plus import from Postman and Insomnia, an example workspace on first launch, and a response tree that stays fast on very large payloads.

## Schema browser

Click any type — in the sidebar, in a field's type, in "used in" — and it opens as a documentation page: description, fields with arguments and default values, deprecations with reasons, enum values, interfaces and implementations, and every place the type is used. Type names are links; the tab keeps back/forward history like a browser. Root fields have **Insert query**, which builds an operation with a selection set and variables. The sidebar lists root fields, searches fields across all types and groups the rest by kind (objects, inputs, enums, interfaces, unions, scalars).

## Large responses

The response tree now renders only the rows in view. Expanding an array of 20 000 objects keeps a few dozen DOM nodes instead of hundreds of thousands; search and expand/collapse work the same.

## Import

Settings → Collections **+** → **Import from Postman or Insomnia**. Supported: Postman Collection v2.1, Postman Environment, Insomnia export v4. Folders become collections, nested folders prefix the operation name, only GraphQL requests are taken (the rest are counted as skipped), and `{{ _.var }}` templates become `{{var}}`. A preview shows what will be created before anything is written; existing collections are never overwritten.

## First launch

The welcome screen offers **Open the example**: a workspace on a public countries API with three queries, an environment variable and a smoke flow with extraction and an assertion. Import is available from the welcome screen as well.
